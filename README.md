# ШУМ — лаборатория прогнозов

Рабочая панель для анализа потока задач: импорт CSV, метрики, эвристики перегрузки, 600 воспроизводимых симуляций, сценарии мощности и потока, диапазон P10–P90 и экспорт прогноза. Переключатель «СЛОП» переводит рекомендации в ироничный корпоративный шаблон.

## Запуск

Node.js 22.13+ (для тестов — 22.18+), npm.

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run lint
npm run build
```

React 19 + TypeScript + Vinext/Vite, доступные элементы Base UI / Shadcn, адаптивный интерфейс и SVG-визуализация. Сайт экспортируется статически: сервер, база и API-ключи не требуются. Для публикации Sites используется `.openai/hosting.json`. Собранные публичные файлы находятся в `dist/client/`.

## Входные данные

CSV содержит `date,incoming,completed`: ISO-дата, число поступивших и завершённых задач. Поддерживаются BOM, CRLF, запятая / точка с запятой / табуляция, русский заголовок `дата,поступило,завершено`, изменение порядка столбцов и простые значения в кавычках. Вложенные кавычки и многострочные поля не поддерживаются и не нужны для этих трёх типов данных.

От 7 до 366 последовательных календарных дней, целые значения 0–100 000; максимум 100 КБ. Укажите очередь до первого дня. Дни без задач включаются нулевыми строками. Пропуски, повторы дат, невозможные даты и выполнение сверх доступной очереди отклоняются. Исходные данные остаются только в памяти вкладки и теряются после обновления страницы; отправки данных нет. Экспорт сохраняет прогноз на устройство.

## Методика и ограничения

- Историческая очередь: начальная очередь + накопленная разница поступления и выполнения.
- Средние и коэффициент вариации: последние 14 дней (либо все доступные).
- Входящий поток: линейный тренд с затухающим продолжением `last_fitted + slope * 7 * (1 - exp(-h/7))`, ограниченный диапазоном 0–100 000 до применения сценария.
- 600 симуляций с фиксированным seed и парным выбором остатков тренда / выполнения. Сценарий масштабирует поступление и выполнение; очередь не может быть отрицательной. Baseline использует те же выборки без изменений. Краткий прогноз совпадает с префиксом длинного.
- P10–P90: центральные 80% результатов модели, **не откалиброванный вероятностный доверительный интервал**.
- Индекс: `50*clamp((load-0.8)/0.7) + 30*clamp(queueDays/10) + 20*clamp(CV/0.5)`, clamp в [0,1]. Пороги 35 и 65. Это эвристическая оценка, а не вероятность.
- Рекомендация: `(meanProjectedDemand + queue/horizon)/meanCompleted - 1`; в интерфейсе округляется вверх до 5%, диапазон применения 0–100%. При нулевом выполнении рекомендация недоступна.

Модель не учитывает сезонность, сложность задач, зависимости, новые процессы и внешние события. Фактическое выполнение может недооценивать доступную мощность при малом объёме работы. Горизонт 30 дней при короткой истории особенно неопределёнен. Нейросеть не используется: «СЛОП» — локальный ироничный шаблон, не AI API.

## Проверки

`tests/analytics.test.mjs` проверяет сохранение объёма работы, крайние значения, CSV, воспроизводимость, согласованность горизонтов, влияние сценариев и экспорт. `npm run typecheck` проверяет приложение и компоненты. GitHub Actions запускает проверки и сборку для push/PR.

Сгенерированный каталог `components/ui` и его `use-mobile` проверяются TypeScript, но исключены из линтера приложения: оригинальный шаблон содержит несовместимые с его же правилами lint-паттерны. Прикладные компоненты, модель и WebMCP-хук проходят полный lint.

При поддержке `document.modelContext` регистрируется необязательный WebMCP-инструмент `run_queue_forecast`: тот же валидатор, модель и видимое состояние. Ошибка проверки не изменяет текущие данные. Обычный интерфейс работает без WebMCP.
